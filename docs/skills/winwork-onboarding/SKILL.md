# Онбординг WinWork

Рабочий проект: `/Users/ralphquite/Documents/Cursor projects/winwork-presentation`. Этот файл — канонический навык внутри репозитория; установленная копия в `~/.codex/skills/winwork-onboarding` ссылается на эту папку. Если проект перенесён, используй его актуальный корень.

## Начать здесь

Прочитай `AGENTS.md`, затем только область `offline-onboarding` в `docs/agents/context-index.json`. Текущий контракт и карта файлов — в [docs/onboarding.md](../../onboarding.md); правила карточек — в [onboarding-ux-rules.md](../../../prompts/onboarding-ux-rules.md). Не исследуй заново презентации, Court и старые Pencil-флоу, если задача их не затрагивает.

Цель: дать новому пользователю выполнить полезный сценарий внутри точной React-копии WinWork. Одновременно доступны каталог сценариев, помощь в плашке «Обучение» после колокольчика и один HTML без сервера. Это демонстрация, без продуктового API и реальных заявок.

Второй сценарий — `CompanyOnboardingDemo.tsx` и `companyState.ts`: главная → настройки → информация о компании → логотип и шесть полей публичного профиля → сохранение. Результат из dev-кода: «Публичный профиль обновлён». Независимый ключ — `winwork.onboarding.company.v1`; завершение требует всех фикстур и сохранения.

Третий сценарий — `MarketplaceOnboardingDemo.tsx`, `MarketplaceTaskForm.tsx`, `marketplaceState.ts`: главная → маркетплейс → одиночное задание → заполнение → создание → строка → информация и отклики. Источник — Dev для ООО «Ф», просмотренный 21.09.2026; пользователь явно разрешил создать тестовое задание. В новых задачах это разрешение не переносится на другие публикации. Новый ключ — `winwork.onboarding.marketplace.v1`, hash — `#marketplace`. Формы создания и чтения общие, прогресс завершён только после открытия созданной строки, отклики остаются нулевыми. Адрес и удалённый режим, второе наименование работ, независимый сброс и пауза поддержаны.

Первый сценарий: главная → «Мой тариф» → «Оставить заявку» → данные представителя и селфи → «Отправить». Успех: «Заявка успешно отправлена» / «Спасибо! В ближайшее время с вами свяжется наш специалист.». Этот результат подтверждён кодом dev-фронтенда 21.09.2026, без реальной отправки. Ставка остаётся 7%; подача заявки не равна одобрению и не гарантирует 3%.

Пополнение счёта — `TopUpOnboardingDemo.tsx` / `topUpState.ts`, hash `#topup`, ключ `winwork.onboarding.topup.v1`. Порядок каталога/помощи: тариф → пополнение → компания → первое задание. Четыре шага: «Мой тариф» → вкладка «Пополнение» (две подсказки первого шага), общий банк и варианты пополнения, сумма, выбор PDF/Excel и формирование. Последняя подсказка выделяет выбор формата и кнопку вместе; постоянной подписи о демо-сумме нет. «Тариф» и «Пополнение» — отдельные вкладки; схема прогресса v3 сохраняет ID банка; старые v1/v2 используют Т-банк по умолчанию, прежние страницы tariff/invoice мигрируют во вкладку topup с сохранением ключа. Смена банка обновляет QR, счета и реквизиты, сохраняет сумму/формат и сбрасывает готовность счёта. Завершение — подготовленный бланк; баланс не увеличивается. Финал тарифа ведёт к пополнению, финал пополнения — к первому заданию. `TariffPage.tsx` переиспользуется обоими сценариями, `TariffPage` владеет общим локальным или управляемым состоянием; `TopUpInvoice` получает его через props. `bankRequisites.ts` содержит три набора демо-реквизитов и копирование; `topUpAssets.ts` связывает каждый банк с его встроенными PDF/XLSX и QR. Кнопки сброса находятся внутри каждой карточки каталога, отдельными от кнопок открытия, и очищают только свой сценарий.

## Добавить следующий флоу

1. Уточни из запроса начало, полезный результат и нужные страницы. Посмотри только новые состояния в разрешённой вкладке WinWork. Сними размеры, шрифты, отступы, состояния панели/формы и исходные ассеты при том же viewport. Не придумывай результат необратимого действия: проверь доступный код фронтенда или запроси описание у пользователя, если наблюдать его без реальной отправки нельзя.
2. Сохрани узнаваемый интерфейс пиксельно точно, включая пустые и заполненные состояния. Скопируй доступные исходные иконки/шрифты; реальные данные замени согласованными вымышленными. Используй семантический React, а не полноэкранные скриншоты с хотспотами. Существующая оболочка онбординга — отправная точка; меняй её только по подтверждённому новому интерфейсу.
3. **Демонстрационный ввод по клику — выбранное пользователем поведение.** Каждое поле получает фиксированное демо-значение по клику или Enter/Space; Tab только фокусирует. Загрузка по клику сразу добавляет демо-вложение. Не открывай файловый диалог и не требуй печатать паспортные данные. Повторный клик не дописывает значение и не создаёт дубликат. Не заполняй через `onFocus`: это меняет данные при обходе Tab и может дублировать ввод. Внешний вид исходных полей сохраняется; подсказка о демо-режиме отделена от продуктового текста.
4. Определи локальные состояния страниц и проверяемый результат каждого действия. Сначала рабочий путь без обучения, затем подсказки. Проверяй готовность после клика по полю **и** после вложения, в любом порядке. Завершение засчитывай по успешному локальному результату, а не открытию формы.
5. Добавь флоу в оба списка: внешний каталог и «Первые шаги» внутри WinWork. Каталог уже содержит `#tariff`, `#topup`, `#company` и `#marketplace`; общие главная/меню/шапка находятся в `OnboardingShell.tsx`, помощь — в `OnboardingHelp.tsx`. `OnboardingTour` принимает название, число шагов и необязательную область `avoidTarget`, за пределами которой размещает карточку. Добавляй только реальные общие параметры; не копируй её целиком и не создавай универсальный движок заранее. Сохрани `#tariff` и ключ его прогресса.
6. Первый вход показывает закрываемое приглашение. Карточка объясняет пользу и действие в 1–2 предложениях, содержит название сценария, шаги и возврат. «Далее» — для информационных шагов; переход после действия — по фактической готовности. Крепи карточку через `data-tour-target`, не к координатам. Не перекрывай цель и ошибки. При уходе со страницы — пауза/возврат; помощь позволяет продолжить или повторить. Проверь фокус, Escape, Tab и узкое окно.
7. Сохраняй только этапы и идентификаторы встроенных фикстур; у нового флоу свой ключ/состояние. Не сохраняй пользовательские значения и содержимое файлов. Перезагрузка повторно проверяет готовность; недоступный storage не ломает текущий сеанс. Сброс одного сценария не должен стирать остальные.
8. Подключи новые ассеты через импорты, чтобы они попали в офлайн-сборку. Веб и HTML используют одни компоненты. `/onboarding` остаётся защищённым маршрутом; публичный Court и его bundle не расширяются. Не добавляй onboarding-флоу в `DemoFlowId` презентаций без отдельного требования.

## Проверить и передать

- Пройди сценарий только кликами; отдельно проверь клавиатуру, пустую форму, повторные клики, удаление/повтор вложения, вложение до заполнения последнего поля, возврат, паузу/продолжение, закрытие/повтор открытия, reload и reset. После нового флоу проверь сохранность тарифного.
- Обязательно проверь **заполненные** поля, включая email/tel и сумму счёта: значение ниже плавающей подписи, отступы и ширина сохранены. В `onboarding.css` селекторы `.wo-field input, .wo-field select` должны оставаться вместе в правиле размеров/отступов; `[readonly]` меняет только курсор. Визуального осмотра пустой формы недостаточно.
- У текстовых полей WinWork нет синей обводки при активации: это явно подтверждено пользователем. Сохраняй локальное исключение для `.wo-field input:focus` / `select:focus`; не добавляй декоративную рамку обратно. Фокус кнопок и выделение целей онбординга остаются отдельными стилями.
- В `TariffPage.tsx` общий выбор банка стоит над тремя карточками: QR над формой слева, реквизиты справа. `TopUpInvoice.tsx` содержит форму с выбором PDF/Excel; сумма 25 000 ₽ по клику, скачивание встроенных демо-бланков, безопасный QR-маркер. Источник скачивает файл, не отправляет email. Не создавай реальный счёт при проверке. Для другого флоу переиспользуй только реально общие элементы.
- Сравни новые экраны с источником на одинаковом viewport. `design-qa.md` содержит только реально полученные результаты, включая ограничения проверки.
- Запусти `pnpm check`. Команда также собирает `dist/offline/Открыть онбординг WinWork.html`; отдельная сборка — `pnpm build:onboarding:offline`. Проверь HTML без сети, отсутствие внешних ресурсов и ошибок консоли, если инструменты допускают запуск `file://`.
- В предыдущей сессии Browser Use блокировал `file://`, а загрузке файла не хватало разрешения расширения. Это ограничения той среды, не доказательство неисправности HTML. Не обходи текущий запрет инструмента и не заявляй непроведённую проверку. После перехода на демо-вложение файловый диалог для сценария не нужен.
- Обнови `docs/onboarding.md` и область `offline-onboarding`, когда меняются структура, команды или контракты. Передай ссылки на локальный каталог и пересобранный HTML. Коммит, пуш и деплой требуют соответствующей задачи пользователя.
