# Источники контекста и актуальность

Сверка выполнена **16 ноября 2026 года**. Этот реестр нужен, чтобы новый участник мог проверить основание решения, не перечитывая всю историю. Краткая база — [WinWork](README.md), функциональные подробности — [features.md](features.md), назначение артефактов — [контекст проекта](../project-context.md).

## Как выбирать источник

1. **Поведение локального проекта** определяют текущий код, `package.json`, конфигурации и используемые assets. Количество файлов экспорта не равно числу активных сцен.
2. **Цель и продуктовые требования** определяют прямые объяснения пользователя; позднее уточнение заменяет раннее. Это не автоматически подтверждает выпуск в production.
3. **Дизайн конкретной поверхности** задают согласованные Pencil/Figma и замечания пользователя. Стиль портфолио не переопределяет стиль кабинета.
4. **Подробное описание продукта** дают сохранённые материалы с датами и происхождением. Оно шире реализации этого репозитория.
5. **Ответы ассистентов, планы, старые метрики и примеры** сохраняют статус предложения/исторического свидетельства до подтверждения. Не объединяем их в вымышленную текущую спецификацию.

Для текущих нормативных, юридических, тарифных и production-утверждений нужна отдельная проверка владельца или актуального первичного источника. В этой работе восстанавливался контекст, а не проводилась такая проверка.

## Как разрешены противоречия

| Расхождение                                                    | Правило для дальнейшей работы                                                                                                                                            |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Начальное «никакого offline» / поздние автономные задачи       | Действует позднее решение и существующие автономные сборки                                                                                                               |
| «Только презентация» / новые функции                           | С 16 ноября пространство также для проектирования/прототипирования WinWork; production-интеграции не подразумеваются                                                     |
| Старые 17 этапов / 37 экранов подрядной схемы                  | Текущий полный прототип: 15 этапов / 35 экранов; краткая версия: 10 статичных слайдов                                                                                    |
| Старый порядок подтверждения                                   | Исполнитель подтверждает → подрядчик подписывает → заказчик принимает/оплачивает                                                                                         |
| Новая вкладка отчёта / одно окно                               | Новая вкладка — намерение для продукта, одно окно — явное требование к HTML                                                                                              |
| Общие отчёты «по дате оплаты» / подрядные                      | Нынешний подрядной прототип отбирает по дате начала задания; не объединять формулы                                                                                       |
| Фиксированная блокировка / выбор месяцев                       | Позднее добавлен выбор срока, отдельное отключение автоблокировки убрано                                                                                                 |
| Проверки только переквалификации / другие риски                | Пользователь прямо расширил формулировку на несколько видов рисков                                                                                                       |
| «Без приложения» / «без регистрации»                           | API допускает отсутствие мобильного приложения, но первичная веб-регистрация WinWork остаётся                                                                            |
| Массовое подключение своего пула / новые кандидаты             | Главный акцент привлечения — маркетплейс; свой пул дополняет общий поток откликов                                                                                        |

| Портфолио-карточки / функционал WinWork                        | Не импортировать соседние продукты и placeholders как модули                                                                                                             |
| НПД/НДФЛ в старом запросе и `smb-10`                           | Область автоматизации требует уточнения; Court фиксирует условие поручения для НПД. Редакционная ошибка заголовка `smb-10` не исправлялась этой документационной задачей |
| Старые маркетинговые числа / бизнес-отчёты                     | Хранить период, определение и источник; не выбирать большее автоматически; не выдавать внутренние финансы за публичный контекст                                          |

## Поддержание контекста

При новом решении добавляйте короткое правило в тематический документ и источник/дату здесь. Не копируйте целые чаты, повторяющиеся предложения ассистентов, реальные реквизиты или временные пути вложений. Если новая задача меняет прежнее решение, явно укажите, какое уточнение заменено. При изменении реализации синхронизируйте документацию и [маршрутизатор](../agents/context-index.json), затем выполните документационные проверки.
