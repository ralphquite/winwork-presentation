# Отчёты по подрядной схеме

Самостоятельный интерактивный прототип для заказчика и подрядчика. Он продолжает [подрядную схему](contracting.md): сторонам нужно видеть задания и расчёты за период с конкретной компанией или со всеми контрагентами.

## Что попросил пользователь

В исходном кабинете отчёты можно было скачать в XLS, но нельзя было просмотреть. Задача — спроектировать вкладку «Отчёты» внутри подрядной схемы: список готовых примеров, кнопку формирования, настройки выборки, состояния «Формируется» / «Сформирован», просмотр таблицы и скачивание Excel. Основание — Codex «Спроектировать отчёты по подрядчикам»; идентификатор и уточнения в [реестре источников](winwork/sources.md).

У **заказчика** контрагентом является подрядчик: какие задания выполнены через него и какие суммы ожидают оплаты. У **подрядчика** контрагентом является клиент-заказчик: какие задания пришли от клиентов, что завершено и оплачено. Исполнитель участвует в заданиях, но отдельного кабинета отчётов для него в этой задаче нет.

Для будущего продукта обсуждалось открытие отчёта в новой вкладке. Для автономного HTML пользователь прямо уточнил: открывать в том же окне, сохраняя возврат в раздел. Это намеренное различие.

## Два типа отчётов

| Тип                              | Одна строка                      | Поля                                                                   |
| -------------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| Реестр заданий                   | Одно задание выборки             | Номер, название и объект, подрядчик/клиент, дата начала, статус, сумма |
| Сводка по подрядчикам / клиентам | Компания с подходящими заданиями | Компания, всего заданий, завершено, ожидает оплаты, оплачено           |

Типы `tasks` и `summary` — текущая реализация задачи в [data.ts](../src/contracting/reports/data.ts). «Реестр заданий» здесь — отчётная таблица, не реестр запуска массовой выплаты. Отчёт не подписывает акты и не проводит расчёты.

## Сценарий и настройки

1. Открыть подрядную схему и выбрать «Мои подрядчики» или «Работа в режиме подрядчика».
2. Перейти в «Отчёты». У каждой роли четыре готовых примера; списки независимы.
3. Нажать «Сформировать отчёт»: выбрать тип, компанию или все компании, начало и конец периода, все статусы / только завершённые / выбранный набор.
4. Проверить предложенное название и количество подходящих заданий. Название можно изменить. Форма объясняет пустой результат и не принимает неверный период или пустой произвольный набор статусов.
5. Новый отчёт появляется как «Формируется», затем уведомление «Отчёт готов» предлагает открыть его.
6. Просмотреть таблицу, параметры и итоги, найти строки, скачать XLSX или создать похожий отчёт.
7. Вернуться к списку с сохранёнными фильтрами и сортировкой. При смене роли остаётся вкладка «Отчёты».

В списке есть поиск, фильтры типа, компании и готовности, сброс и сортировка по времени создания. Фильтр компании отбирает отчёты, **сформированные именно по этой компании**, а не ищет её строки внутри отчёта «Все компании».

## Смысл данных

Период включает обе даты и относится к **дате начала задания**, не к дате оплаты, подписи или формирования отчёта. Дата формирования показана отдельно. Не переносить сюда исторический принцип общих отчётов WinWork «по дате фактической оплаты»: это другая выборка.

Статусы заданий: «Опубликовано», «Выполняется», «На подтверждении», «Ожидает оплаты», «Завершено», «Отменено». Статус готовности отчёта — другая сущность.

В `data.ts` «Завершено» одновременно учитывается в количестве завершённых и в сумме «Оплачено». «Ожидает оплаты» попадает в сумму к оплате. Остальные статусы не увеличивают эти денежные суммы. Это правило **синтетических данных прототипа**, не утверждённая бухгалтерская формула production WinWork. Для реальной реализации нужно согласовать платёжные статусы, частичную оплату, возвраты, комиссии и момент фиксации данных.

Поиск внутри просмотра меняет только видимые строки. Экранные итоги считаются по всей исходной выборке. XLSX содержит параметры и **все строки сформированного отчёта**, независимо от поиска; отдельный блок общих итогов в файл сейчас не выгружается. Выгрузка имеет формат `.xlsx`, хотя в постановке использовалось общее обозначение XLS/Excel.

## Локальная реализация

```bash
pnpm build:contracting:reports
```

Файл: `dist/offline/Отчёты — подрядная схема WinWork.html`. Открывать в Google Chrome. Прямые входы — `#/customer/reports` и `#/contractor/reports`: hash-пути внутри файла, не маршруты опубликованного сайта. Обычная сборка пяти подрядных презентаций отчёты не создаёт.

| Файл                                                                        | Ответственность                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------- |
| [ContractingReports.tsx](../src/contracting/reports/ContractingReports.tsx) | Роли, навигация, созданные отчёты, хранение и уведомления     |
| [ReportForm.tsx](../src/contracting/reports/ReportForm.tsx)                 | Настройки, название, предварительная выборка и проверка ввода |
| [ReportViews.tsx](../src/contracting/reports/ReportViews.tsx)               | Списки компаний/отчётов, фильтры, просмотр                    |
| [data.ts](../src/contracting/reports/data.ts)                               | Fixtures, статусы, выборка, колонки и итоги                   |
| [workbook.ts](../src/contracting/reports/workbook.ts)                       | Формирование и скачивание XLSX                                |
| [reports.css](../src/contracting/reports/reports.css)                       | Таблицы и форма в стиле WinWork                               |
| [offline-main.tsx](../src/contracting/reports/offline-main.tsx)             | React-вход с HashRouter                                       |

Используется общая `ContractingShell`. Формирование имитируется локальным временем готовности, без серверной очереди. В `localStorage` (`winwork.contracting.reports.v1`) сохраняются параметры созданных отчётов; строки вычисляются из fixtures. Если хранение недоступно, появляется предупреждение. Это не неизменяемый архив отчётных данных.

Последнее уточнение дизайна: обычный шрифт таблиц WinWork, без жирных синих названий-ссылок; кликабельность и доступ с клавиатуры сохраняются. Текущее оформление использует Roboto и компактные строки.

## Проверки и будущие вопросы

Для кода нужен `pnpm check`, затем отдельные `pnpm build:contracting:reports` и `pnpm test:contracting:reports`: отчётный тест не входит в общий gate. В Chrome без сети проверить обе роли, создание/готовность, период/статусы, пустой результат, сохранение, возврат/историю, XLSX, Escape/фокус формы и узкий экран. Дизайн сверять с Figma исходной задачи и существующим кабинетом.

Для production отдельно уточняются права, полный набор типов, источники/формулы, ошибки формирования, хранение снимка, объём/пагинация, комиссии и корректировки. Эти вопросы не становятся готовыми возможностями от наличия прототипа.
