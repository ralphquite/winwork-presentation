# WinWork — презентации и прототипы продукта

Локальное рабочее пространство для объяснения WinWork, проектирования новых функций и проверки пользовательских сценариев. Здесь собраны презентации для продаж и суда, подрядная схема, онбординг, отчёты и другие интерактивные прототипы. Название папки `winwork-presentation` сохранено, но назначение проекта уже шире презентаций.

**WinWork** помогает компаниям работать с внештатными исполнителями: найти или подключить людей, разместить задания, оформить документы, принять результат и провести выплаты. У продукта есть веб-кабинет бизнеса, приложение руководителя объекта, приложение исполнителя и API.

**В этом репозитории** интерфейсы работают с локальными состояниями и вымышленными данными. Производственного backend, реальных регистраций, подписаний, выплат и продуктовых API здесь нет. Новые функции проектируем и прототипируем в этой папке; подключение реальных сервисов требует отдельной задачи. На Vercel sales-раздел защищён общим паролем, а `/court` публичен.

## Текущее состояние

- `/enterprise` — готовый маршрут из 17 экспортированных Pencil-слайдов.
- На сценах `ent-04`, `ent-05`, `ent-07`, `ent-08` и `ent-09` доступны пять интерактивных React demo-flow: создание объекта, работа управляющего, создание вида деятельности, шаблоны документов и одиночное задание.
- `/small` — готовый маршрут из 12 экспортированных Pencil-слайдов; сцена `smb-06` переиспользует demo-flow одиночного задания.
- `/api` — готовый маршрут из восьми экспортированных Pencil-слайдов без интерактивных demo-flow; неудалённые сцены сохраняют прежние deep-link ID, удалённый `api-03` остаётся недоступен, финальный слайд — `api-17`.
- `/court` — открытый маршрут из шести слайдов для демонстрации доступности сервиса заказчикам и исполнителям; первые пять собраны кодом, финальный `court-06` со статистикой экспортирован из Pencil. На `court-02` отдельные CTA открывают React-flow регистрации юридического лица и создания одиночного задания, на `court-03` — компонентные flow регистрации исполнителя и пути отклика исполнителя, на `court-04` — выбор исполнителя, а на `court-05` — подтверждение оплаты.
- `/` — экран выбора маршрута и быстрый доступ к standalone flow, включая выбор исполнителя по трём откликам, регистрацию исполнителя из 11 Figma-состояний и путь отклика исполнителя из Figma-состояний 2.1–2.3; экран загрузки «Мой налог» использует утверждённый исходный скриншот.
- `middleware.ts` и `api/auth/login.ts` — Vercel access gateway: парольный экран, проверка credential, подписанная 30-дневная cookie и защита sales-маршрутов/assets. Публичный court-раздел имеет узкий allowlist и отдельный bundle.

Текущая сцена хранится в `?scene=<id>`, например `/enterprise?scene=ent-04`. Прямые ссылки, browser Back/Forward, выбор сцены, стрелки клавиатуры, reset и fullscreen используют один общий движок.

## Быстрый старт

Требуются Node.js 24, pnpm 11.3.0 и Google Chrome для браузерных проверок. Подробный рабочий процесс и действия Codex описаны в [docs/development.md](docs/development.md).

```bash
pnpm install --frozen-lockfile
pnpm doctor
pnpm dev
```

Vite запускается на `http://127.0.0.1:5173` без парольного шлюза; занятый порт вызывает явную ошибку. Открывайте URL в Google Chrome. Для проверки production build без Vercel Middleware используйте:

```bash
pnpm build
pnpm preview
```

## Оффлайн-презентация для суда

Соберите автономный Court-вариант командой:

```bash
pnpm build:court:offline
```

Готовый файл появится по пути `dist/offline/Открыть презентацию WinWork.html`. Его можно скопировать на диск или флешку и открыть в Google Chrome. Устанавливать Node.js, pnpm или отдельное приложение на целевом компьютере не требуется.

В один HTML встроены все шесть Court-слайдов, стили, изображения и React demo-flow со слайдов 2–5. Слева снизу всегда видны три кнопки: предыдущий слайд, следующий слайд и возврат на первый. Внутри demo-flow клик мимо целевого действия временно выделяет нужную кнопку только обводкой, без блика. На самих слайдах и в шторке выбора исполнителей таких подсказок нет. Навигация сохраняется в hash-части локального URL, поэтому browser Back/Forward работает без сервера. Сама презентация не делает сетевых запросов; только явный переход по внешней ссылке на реестр ФНС требует интернет.

## Все презентации для продаж в одном офлайн-файле

`pnpm build:sales:offline` создаёт `dist/offline/Открыть продажи WinWork.html`. Скопируйте этот **один файл** на другой компьютер и откройте двойным кликом в браузере. Пароль, интернет, сервер и установка приложения не нужны.

Открывается та же главная: «Крупный бизнес» (17 слайдов), «Малый бизнес» (12), «API / Embedded» (8), все 10 интерактивных демо и онбординг с четырьмя сценариями. Работают обычные кнопки презентации, выбор слайда, стрелки клавиатуры, F, сброс, возврат на главную и история браузера. Все шрифты, изображения и демонстрационные PDF/Excel встроены. Онлайн-версия продолжает использовать парольный шлюз.

## Подрядная схема офлайн

Заказчик управляет заданием, приёмкой и оплатой; подрядчик оформляет отношения с исполнителем; исполнитель выполняет работу. Презентация показывает один процесс с трёх сторон. Краткая версия объясняет три основных действия на десяти статичных слайдах, а полная содержит подробный пошаговый прототип.

`pnpm build:contracting:offline` собирает полную версию, прототип без слайдов, отдельные презентации для заказчика и подрядчика и краткую презентацию для заказчика. Все пять HTML сохраняются в `dist/offline/` и открываются напрямую в Google Chrome. Имена файлов, порядок показа и сборка выбранных вариантов описаны в [docs/contracting.md](docs/contracting.md).

### Отчёты по подрядной схеме

`pnpm build:contracting:reports` создаёт `dist/offline/Отчёты — подрядная схема WinWork.html`. Это отдельный интерактивный прототип: у заказчика отчёты по подрядчикам, у подрядчика — по клиентам. Можно выбрать период и статусы, сформировать реестр заданий или сводку, просмотреть таблицу в том же окне и скачать XLSX. Постановка, смысл данных и границы реализации — в [docs/reports.md](docs/reports.md).

### Прототип таблицы «Мои исполнители»

`pnpm build:performers:offline` создаёт `dist/offline/Мои исполнители — WinWork.html`. Откройте этот файл в Google Chrome. ФИО и ИНН вымышленные; типы ячеек и SVG-значки сверены с [dev-таблицей WinWork](https://my-smz-partner-front-dev.apibank.tech/aggregator/self-employed/executors/all): аватар, флаги стран, подключение «Мой налог», права на уплату НПД, состояния договора/ПДн/ЭДО и способы оплаты (карта, СБП, счёт, отсутствие реквизитов). Можно перетаскивать и скрывать столбцы, менять их ширину, искать, сочетать фильтры с несколькими значениями и применять несколько сортировок по приоритету. Меню заголовка открывает действия над столбцом; в меню «Столбцы» доступны перетаскивание и стрелки ↑/↓. Значки сопровождаются расшифровками в подсказках, фильтрах и карточке исполнителя. Порядок, видимость и ширина столбцов, высота строк, размер текста и размер страницы сохраняются локально, если браузер разрешает хранилище.

## Парольный доступ на Vercel

Шлюз требует две server-only переменные:

- `WINWORK_ACCESS_PASSWORD` — общий пароль отдела продаж, минимум 12 символов;
- `WINWORK_SESSION_SECRET` — случайный секрет подписи, минимум 32 символа. Его не нужно передавать сотрудникам.

Реальные значения нельзя коммитить или называть с префиксом `VITE_`. Укажите их в Vercel Project → Settings → Environment Variables для Production и Preview. Секрет подписи можно сгенерировать командой:

```bash
openssl rand -base64 32
```

Для локальной проверки скопируйте имена из `.env.example` в игнорируемый `.env.local`, заполните оба значения и запустите Vercel runtime:

```bash
pnpm dlx vercel@latest dev
```

Без переменных Vercel deployment намеренно отвечает `503` на защищённые маршруты; `/court` остаётся доступен. Смена пароля или секрета немедленно делает старые cookies недействительными.

## Проверки

`dist/` содержит генерируемые результаты, не редактируемые исходники. `pnpm build` создаёт web/Court и три offline-файла (Court, Onboarding, Sales). Пять подрядных редакций, отчёты и таблица исполнителей имеют отдельные команды. Главная sales-страница не включает standalone-подрядную схему, отчёты и таблицу исполнителей.

Для документации достаточно `pnpm docs:check`, `pnpm format:check` и `git diff --check`. Общий gate проверяет восемь offline HTML, но отдельные отчёты и таблица исполнителей пока не входят в него: нужны их сборки и проверки из [development.md](docs/development.md).

```bash
pnpm check
```

Полный gate проверяет agent-документацию, форматирование, ESLint, TypeScript, auth contract, production build и браузерные smoke-тесты online/offline в Google Chrome. Во время разработки `pnpm check:quick` запускает проверки без сборки и браузера. Доступны отдельные команды:

```bash
pnpm docs:check
pnpm auth:check
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:e2e
pnpm test:offline # после pnpm build
pnpm build
pnpm build:court:offline
pnpm build:sales:offline
pnpm build:contracting:offline
pnpm test:contracting # после pnpm build:contracting:offline
pnpm build:contracting:reports
pnpm test:contracting:reports # после отдельной сборки отчётов
pnpm build:performers:offline
```

## Карта проекта

- `docs/winwork/` — краткая база продукта, карта функций, источники и свежие уточнения из ChatGPT/Codex/portfolio.
- `src/contracting/`, `src/contracting/reports/` — подрядной сценарий и самостоятельный прототип отчётов.
- `src/onboarding/`, `src/performers/` — онбординг и таблица исполнителей.
- `description/` — подробный датированный продуктовый контекст и материалы портфолио; читать по ссылкам из карты функций.
- `For Printing/` — сохранённые кадры Court для печати; они не обновляются автоматически.
- `src/app/` — app composition, landing и маршруты.
- `src/presentation/engine/` — URL state, навигация, reset, fullscreen и scene dispatch.
- `src/presentation/config/` — порядок и метаданные сцен для четырёх tracks.
- `src/court/` и `court.html` — отдельная публичная React-точка входа для `/court`.
- `src/court/offline-main.tsx`, `court-offline.html`, `vite.court-offline.config.ts` и `scripts/package-offline-court.mjs` — отдельная упаковка той же Court-презентации в один автономный HTML.
- `src/app/offline-main.tsx`, `sales-offline.html`, `vite.sales-offline.config.ts` и `scripts/package-offline-sales.mjs` — автономная упаковка sales-маршрутов; `scripts/offline-assets.mjs` — общие функции встраивания ресурсов Court/Sales.
- `src/presentation/slides/` — масштабирование Pencil HTML и demo hotspots.
- `src/presentation/flows/` — компонентные desktop/mobile demo-flow и общие product primitives.
- `src/demos/` — flow bindings и generic synthetic fixtures.
- `middleware.ts` — Vercel password gateway перед SPA и статическими assets.
- `api/auth/login.ts` — Edge Function, принимающая password form и выдающая подписанную cookie.
- `auth/session.ts` — общий server-only контракт cookie, HMAC и env validation.
- `.env.example` — имена обязательных server-only секретов без значений.
- `public/enterprise-slides/` — runtime HTML-экспорты Enterprise и их локальные зависимости.
- `public/api-slides/` — runtime HTML-экспорты API / Embedded и их локальные зависимости.
- `public/small-slides/` — runtime HTML-экспорты Small Business и их локальные зависимости.
- `public/court-slides/` — code-authored и Pencil-exported HTML/CSS-слайды публичной презентации.
- `public/court-assets/` — официальные логотипы ФНС и сервисов сравнения для публичных слайдов.
- `public/performer-registration-flow/` — публичные Figma-ассеты мобильного flow регистрации исполнителя, включая точные логотипы, флаги, иллюстрации и утверждённый экран загрузки «Мой налог».
- `public/performer-response-flow/` — публичные точные Figma-ассеты трёхэкранного мобильного flow отклика исполнителя.
- `public/demo-flows/` — только референсы для visual QA; приложение не рендерит их как интерактивный продукт.
- `pencil/` — редактируемые дизайн-источники и исходные assets.

## Vercel

Проект собирает защищённый Vite SPA и изолированный публичный bundle под `dist/court-app/`. Перед cache и SPA routing Vercel запускает корневой `middleware.ts`: `/court` и его явно перечисленные assets проходят без cookie, остальные запросы требуют подписанную HttpOnly cookie либо получают парольный экран. Парольная форма отправляется в `/api/auth/login`, потому что request body обрабатывает Edge Function, а не Routing Middleware. `vercel.json` направляет `/court` в отдельный HTML-entry, а авторизованные прямые запросы `/enterprise`, `/api` и `/small` — в основной `index.html`.

## Онбординг WinWork

Откройте `/onboarding` или раздел «Онбординг новых пользователей» на главной. Доступны четыре сценария: снижение комиссии (`#tariff`) — главная → «Мой тариф» → заявка → подтверждение отправки; пополнение счёта (`#topup`) — «Мой тариф» → «Пополнение» → варианты реквизитов → сумма и готовый счёт; информация о компании (`#company`) — главная → «Настройки» → публичный профиль → сохранение; первое задание на маркетплейсе (`#marketplace`) — главная → маркетплейс → одиночное задание → заполнение → создание → информация и отклики. Поля и логотип заполняются по клику, без печати и выбора файла. Сброс каждого сценария находится внутри его карточки. Колокольчик стоит перед всеми карточками шапки; «Обучение» открывает список первых шагов; подсказки запускаются при первом открытии и сохраняют прогресс.

`pnpm build:onboarding:offline` создаёт `dist/offline/Открыть онбординг WinWork.html`: один файл, который работает без сервера и интернета. Все данные вымышленные; отправка заявки моделируется локально. Подробности: [docs/onboarding.md](docs/onboarding.md).
